# 行動起点ダッシュボードと判断タブ配置の設計

**日付:** 2026-08-11
**状態:** 実装前レビュー

## 目的

ダッシュボードを、単なる全体集計ではなく、利用者が「自分が次に対応すべき申請」を見つける
入口へ育てる。あわせて、判断タブでは長い AI 判断を読みながら判断操作へ手が届く配置にする。

今回扱うのは 開発メモ（非公開） の D1 と D4 である。Dataverse スキーマ、取得 API、
書き込み処理、アクセス権、Copilot Studio、Power Automate は変更しない。

## D1: 対応が必要な申請

### 表示構成

ダッシュボード下部の「直近の申請」と「期限超過の申請」を、次の2一覧に置き換える。

| 一覧 | 対象 | 次に動く人 |
| --- | --- | --- |
| 提出・修正が必要 | 希望期限を過ぎた Draft | 申請の作成者 |
| 判断が必要 | 希望期限を過ぎた Submitted | 申請に設定された判断者 |

Decided、希望期限がない申請、希望期限が当日の申請はどちらにも表示しない。期限超過は、
利用者のローカル日付で希望期限の日付が今日より前の場合とする。時刻の経過だけで当日中に
期限超過へ変わらない。

各一覧は既存の `ListTable` を使い、タイトル、ステージ、カテゴリ、判断者を表示する。行を押すと
既存どおり申請詳細へ移動する。0件の場合は、一覧名と表示範囲に対応した空状態を表示する。

### 「自分 / 全体」切替

2一覧の共通スコープとして「自分」と「全体」の切替を置き、初期値は「自分」とする。
選択は画面内の状態だけに保持し、URL、Dataverse、ブラウザー保存領域には書き込まない。

| スコープ | Draft の本人判定 | Submitted の本人判定 |
| --- | --- | --- |
| 自分 | `_createdby_value` が現在の Dataverse system user | `_ds_deciderid_value` が現在の Dataverse system user |
| 全体 | 作成者を問わない | 判断者を問わない |

GUID は既存の正規化方法で比較する。関係者やメンション先であることだけでは「自分」に含めない。
この切替は、すでに取得済みのレコードを画面内で絞る表示機能であり、認可境界にはしない。

### 本人情報の状態

「自分」を選んでいる間は、現在ユーザー ID の取得完了前に全件を表示しない。

- 取得中: 本人情報を確認中であることを表示する。
- 取得失敗または ID なし: 本人向け一覧を空にせず、取得できなかったことを明示する。
- 「全体」: 本人 ID の状態にかかわらず、既存の閲覧可能な全レコードから分類する。

## D4: 判断タブの配置

デスクトップの判断タブは、ユーザーが選んだ B 案を採用する。

- 左40%: 「最新判断」と「判断パネル」をまとめた操作レール。
- 右60%: 「AI判断」の読解領域。
- `lg` 以上では左レールを上端付近へ追従させる。
- `lg` 未満では1列に戻し、追従を解除する。

左側の高さを右側へ無理にそろえず、余白を操作レールの一部として扱う。判断の作成可否、入力、
AI 判断更新、空状態などの既存挙動は変更しない。

## 実装境界

期限判定、ステージ分類、スコープによる本人絞り込みは、画面から独立した純関数として
`src/lib` に置く。関数は申請一覧、スコープ、現在ユーザー ID、評価時刻を受け取り、2一覧を返す。
評価時刻を引数にすることで日付境界を決定的にテストする。

`src/pages/dashboard.tsx` は現在ユーザーの取得、切替 UI、純関数の結果表示を担当する。
`src/pages/application-detail.tsx` は判断タブのグリッド比率だけを変更する。既存のサービス、フック、
データ取得件数は変えない。

## テストと確認

### 自動テスト

純関数について少なくとも次を検証する。

- 前日までを期限超過とし、当日と未来日は除外する。
- Draft、Submitted、Decided、未設定または未知のステージを正しく分類する。
- 希望期限なしを除外する。
- 「自分」で Draft は作成者、Submitted は判断者を照合する。
- GUID の大文字小文字や波括弧の差を正規化する。
- 現在ユーザー ID がない「自分」表示で全件を返さない。
- 「全体」は本人 ID の有無で結果が変わらない。

既存の機械的ゲートとして `npm run build`、`npm test`、`npm run lint`、
`npm run test:ai-tooling`、Python の `unittest discover` を実行する。

### 実機確認

- 初期表示が「自分」である。
- 「自分 / 全体」の切替で両方の一覧が同時に更新される。
- 自分が作成した期限超過 Draft と、自分が判断者の期限超過 Submitted が正しい一覧に出る。
- 0件、本人情報取得中、本人情報取得失敗の表示が全件表示に化けない。
- 一覧の行から正しい申請詳細へ移動する。
- デスクトップで左レールが追従し、AI 判断側が広く読める。
- 狭い画面で1列となり、内容の重なりや横スクロールがない。

## 完了条件

上記の自動テストと機械的ゲートが通り、実機確認項目を満たすこと。完了後、
開発メモ（非公開） の D1 と D4、および「現在地」「次にやること」を実測結果に合わせて更新する。

## 対象外と残るリスク

- 期限前だが対応が必要な申請の優先順位付け、通知、件数カードは今回追加しない。
- 関係者やメンションを本人向け一覧へ含めない。
- 一覧の並べ替え規則、設定の永続化、管理者専用ビューは変更しない。
- 画面内フィルターなので、Dataverse のアクセス権を代替しない。
- D4 の見栄えと追従挙動は自動テストだけでは保証できず、実機の画面幅別確認が必要である。
